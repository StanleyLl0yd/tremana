# Interface localization and language roadmap

## Shipped translations in this development slice

The initial native translation package includes **English and Russian**
(`en.lproj` and `ru.lproj`), with parity-validated string tables.

TreMana starts in **System (automatic)** language mode. It checks the ordered
macOS preferred-language list, uses the first language for which a full app
translation is installed, and otherwise falls back to English. Settings >
Language allows an explicit choice; the override persists. Language and
light/dark appearance are independent.

Strings are packaged in the actual macOS application bundle's
`Contents/Resources/*.lproj` and validated in CI and release workflows.
The Swift Package also declares English as its default localization.
Computed interface labels are wrapped in LocalizedStringKey; user-provided
torrent names, file paths and tracker URLs remain unchanged.

Untranslated dynamic daemon messages and native system errors may still
appear in the server/system language; UI acceptance must record those.
Do not mark a locale as complete until dynamic status messages, labels,
action confirmations, accessibility text and date/number formatting are
reviewed on actual macOS.

## Final supported-language target (not all shipped yet)

TreMana intentionally targets a **finite set of high-value languages**.
No blanket requirement to cover every language of Europe or Asia.

**Total: 16 languages and 17 locale resources** (Chinese includes two
written forms). Currently only `en` and `ru` are provisioned; the
remaining 15 locale resources must be translated and accepted before being
listed as available in the app. A supported locale must cover all visible UI,
dynamic action messages, errors and accessibility labels, not just menus.

### Delivery groups

1. **European + Eastern Slavic:** `de`, `fr`, `es`, `it`, `pt`,
   `nl`, `pl`, `uk`, `be`. English and Russian are existing foundations.
2. **Arabic and Hindi:** `ar`, `hi`, including Arabic right-to-left
   layout and Indic font/line-breaking checks.
3. **East Asian:** `zh-Hans`, `zh-Hant`, `ja`, `ko`, including script-aware
   locale matching and CJK typography checks.

System language detection must distinguish Chinese scripts: `zh-Hans` and
`zh-Hant` must not be collapsed into a generic `zh` by splitting the
language tag. The manual Settings picker must use each locale's native name
and retain its exact chosen identifier. URLs, file paths, torrent hashes and
magnet data stay in their original script and reading order.

**Excluded from the agreed scope:** blanket EU-24 coverage, other Slavic
families, Nordic/Baltic/regional European languages, Turkish and other
Southeast/South Asian languages. Additions require a new explicit product
decision rather than an automatic expansion of this matrix.

No bundled third-party fonts, translation services or heavy localization
frameworks. Every added locale must pass translation parity, actual macOS
visual and accessibility checks, and the release-size budget.

## Regression and size expectations

- Locale selection tests cover explicit language, region tags, fallback,
  unknown preferences and empty system lists.
- Key-count parity / InfoPlist localization validation must pass.
- The exact app ZIP includes only useful localized .strings and native code.
- Version 0.1.0 remains immutable; changes are staged for a future reviewed
  0.2.x release, not silently delivered as an update to existing binaries.
