# TreMana 0.3.0 — macOS 27 test release

This numeric version is a **test build requiring user acceptance**, not a completed milestone. Target: Apple Silicon (arm64), Transmission 3.00 / RPC 16 on Keenetic.

## Changes since 0.2.1

- Native toolbar with user-selectable presentation: icons only / icons and labels / labels only. The choice survives relaunch. Disconnect is at the left beside torrent actions; no overlapping fixed-width captions.
- More air and material/glass treatment on the command area and the initial connection hero.
- Files inspector: clearly visible per-file Download / Skip selection and separately Low / Normal / High RPC16 priorities, with server read-back and stale-state guards.
- Torrent right-click **Download files in order…**: actual client-side file queue, using explicit `files-wanted` / `files-unwanted` RPC, never file priorities; original wanted mask restored on completion or disable. Persisted across app restarts; verifies file identity and third-party edits.
- Right-click **Download pieces in order…**: an honest unsupported-capability explanation. Standard Transmission 3.00 / RPC 16 does **not** expose sequential-piece scheduling; the action changes nothing.

## Important limitations and hardware acceptance

- Ordered files are by original torrent file index, among user-selected files. TreMana must be running and connected to advance after each file completes. The next file waits while the Mac sleeps, the app is closed, or the network is unavailable.
- Boundary pieces shared by adjacent files may still be downloaded by Transmission; this is not the separate sequential-pieces feature.
- Test on a **disposable** multifile torrent. Verify progress, file skipping, all three priorities, enable/disable ordered file queue, restart and reconnect, external client drift, and restored wanted mask. Full checklist: `docs/M2-STRICT-FILE-QUEUE.md`.
- M1/M2 device acceptance and full repository-wide milestone audit remain pending. Do not claim completion from automated CI alone.

## Signing

This release workflow **requires** the owner-supplied stable `TreMana Code Signing` certificate to be imported from protected GitHub Actions secrets. The workflow refuses publication rather than creating another ad-hoc signed release. Setup: `docs/KEYCHAIN-SIGNING.md`.

Self-signed Code Signing does **not** grant Apple Developer ID or notarization. Gatekeeper may still require manual launch approval, and the **first migration** from ad-hoc signing may still prompt Keychain once. Test two consecutive signed versions for stable designated requirements.
