# TreMana 0.4.7 — content-sized macOS windows

Regular GitHub Release for macOS 27 / Apple Silicon.

## Fixed

- The disconnected connection window and Settings now measure the intrinsic
  height of their **own SwiftUI form content** with `onGeometryChange`.
  The old `PreferenceKey` measurements could disappear across a ScrollView
  or NavigationStack boundary, leaving stale initial heights of 500/540 pt
  and clipping the bottom of the connection form and the Settings notes.
- The small AppKit window observers now have nonzero SwiftUI layout size
  (1 × 1 pt) and remain mounted in the view hierarchy.
- AppKit frame changes happen on the following main-queue turn rather than
  synchronously within SwiftUI rendering. Repeated geometry updates are
  coalesced to avoid reentrant layout; measurement noise is ignored.
- Both auxiliary windows remain fixed-size for the user and automatically
  change height when content changes: connection errors, saved profile,
  language, adaptive/fixed refresh mode. Scrolling is reserved for content
  taller than the actual visible screen.
- Unit tests cover valid content growth/shrinkage, measurement noise and
  malformed sizes, in addition to screen-bound fitting rules.

The previously fixed observable-model injection, stable code-signing identity,
Keychain permissions, saved inspector layout, RPC operations and design remain
unchanged.

## On-device checks

1. Open disconnected TreMana on a normal display. The full connection form,
   including "Allow unencrypted HTTP", must be visible **without scrolling**,
   and manual window resizing must be disabled.
2. Open Settings with Command+, and confirm the full final explanatory note
   is visible. Toggle refresh mode Adaptive ↔ Fixed; the extra interval row
   must grow/shrink the window automatically.
3. Change the UI language to Russian/English; no controls or notes should be
   cut off. Try both dark/light themes.
4. On a physically short screen, content must remain accessible by scrolling
   rather than extending below the screen.
5. Reconnect, verify torrent window remains manually resizable, and confirm
   last inspector tab and split height are still remembered.
6. The earlier SwiftUI environment crash fix (0.4.6) must remain stable.

Swift compilation, CI tests and signed release verification cannot replace
real macOS 27 device checks. Final hardware acceptance and repository-wide
audit remain pending.
