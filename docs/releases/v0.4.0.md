# TreMana 0.4.0 — Zen glass UI, macOS 27 acceptance release

Version `0.4.0` is a numbered **user test build** for macOS 27 Apple Silicon. No beta/RC suffix in the app version, tag or ZIP filename.

## User-approved design changes
- Compact native table of multiple torrents at the top; resizable torrent detail inspector always below, never on the right and no full-screen inspector mode.
- More airy native warm translucent materials, restrained blue progress, simple navigation and fewer redundant controls.
- One checkbox per file to include/exclude download; no second toggle on the right. Per-file Low/Normal/High priorities remain separate menus, and size/progress align as columns.
- Read-only top-level Priority summary is based on actual fileStats returned by Transmission 3.00 RPC16: Low/Normal/High if identical across files, **Mixed** if different, **—** if missing. No fictional torrent-wide priority setting.
- Only one Settings entry in the sidebar (and native macOS Settings menu); redundant toolbar settings removed. Search on main toolbar; connected profile menu offers Disconnect. Three toolbar label modes remain configurable in Settings.
- Sidebar includes All / Active / Completed / Paused with counts. User-configurable table columns remain available (new default layout resets the first-run preset).
- New automated tests cover actual file-priority aggregation and missing metadata.

## Hardware acceptance checklist
- macOS 27+ arm64, light/dark and English/Russian, window sizes from 840×560 through full screen.
- Select torrents, drag the horizontal splitter, scroll file list, change file wanted status and per-file priorities; verify updates against Keenetic Transmission 3.00/RPC16.
- Confirm Mixed appears for differing priorities, even if some files were skipped. Unknown/missing metadata displays —.
- Test search, context menus and strict ordered file queue; sequential pieces remain unsupported by Transmission 3.00/RPC16 and display a clear limitation rather than a fake toggle.
- Check migration from the already signed 0.3.0 identity to 0.4.0: the Keychain should not request reauthorization solely due to a changing signing certificate.

## Security and packaging
GitHub Actions imports the owner-pinned `TreMana Code Signing` certificate from environment secrets, verifies the code signature and stable designated requirement, packages arm64 app with numeric version, downloads ZIP back and compares bytes. The signed app is still **not Apple-notarized**: Gatekeeper can require first-run user approval.

**No M1/M2 Keenetic hardware acceptance or final repository-wide audit is implied by passing CI.** Previous releases and protected main remain unchanged.
