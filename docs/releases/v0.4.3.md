# TreMana 0.4.3 — consistent tint and deferred Keychain access

Signed macOS 27 / arm64 acceptance build. Physical verification remains pending.

- The disconnected grouped connection form now uses the same soft burgundy/pink
  background as the connected torrent screen. The form no longer masks the
  application tint behind an opaque black scroll background.
- Loading or selecting saved profiles no longer reads the Keychain password.
  A matching stored credential is queried only after an explicit **Connect**.
  Before that first lookup, the hint does not claim the password is verified.
- The long-lived signing identity, bundle identifier, Keychain account/service
  identifiers and restricted app ACL remain unchanged. macOS may still request
  a one-time authorization after updating the application or system.
  Choose **Always Allow** only for the recognized signed TreMana, never for
  every application.
- Existing context-menu file actions, split view and strict file queue remain
  unchanged.

## Acceptance checks

1. Compare disconnected and connected screens in light/dark: the same gentle
   tinted material should fill both areas behind the glass cards.
2. Install over 0.4.2; opening the profile view or switching profiles must
   **not** prompt for Keychain access before Connect.
3. Press Connect using the saved password; allow the known updated app once if
   prompted. Quit/relaunch and reconnect. A recurring request must be diagnosed.
4. Retest multi-file right-click selection, split-view sizing and RPC connection.

CI verifies source/tests/packaging and a stable signing requirement.
macOS Keychain behavior on the user's Mac and repository-wide audit remain
unverified.
