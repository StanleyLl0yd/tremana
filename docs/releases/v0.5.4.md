# TreMana v0.5.4 — reliable column widths and fit-to-content

Regular signed macOS 27 Apple Silicon release. v0.5.3 remains unchanged.

## Changes

- Fix independent width persistence for the torrent list and file inspector.
- The width probe now retries attachment when SwiftUI inserts/recreates the
  native NSTableView, rather than relying only on the probe's first layout pass.
- Widths are saved on AppKit's column-resize notification, after mouse-up,
  when the window resigns key, and at application termination. Duplicate writes
  are avoided; hidden columns' previously saved widths are retained.
- Column matching uses stable customization identifiers first, then both
  NSTableColumn.title and the header-cell title with locale-insensitive matching.
  It also checks the table's own accessibility identifier and its ancestors.
- Double-clicking a header divider retains native AppKit fit-to-content behavior:
  the column on the left is sized using its cell contents. Mouse events are
  deliberately passed through; the persistence probe does not consume them.
- Existing column visibility/order state remains in SceneStorage. Torrent-list
  and inspector widths remain independent.

## Acceptance

1. Resize several columns in the torrent list, quit TreMana completely, relaunch,
   and confirm each width is restored.
2. Resize several file-inspector columns, switch inspector tabs, quit and relaunch;
   confirm the widths are restored independently of the torrent list.
3. Double-click the divider after Name, Size, Progress, Download, and Priority.
   Only the column on the left should fit its content; other widths stay unchanged.
4. Repeat in Russian and English, with torrent columns hidden/reordered, and after
   changing the main window size.
5. Confirm the native header remains draggable and column visibility/order remain
   unchanged.

The exact-head macOS 27 build, Swift tests, localization checks, source guards,
signed package and release metadata are checked by CI. Hardware acceptance remains
pending.
